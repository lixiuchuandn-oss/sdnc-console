# 5. 高可用与业务连续性

## 5.1 多层次高可用机制

- **控制平面 HA**：管理节点可采用 3 节点集群部署，通过分布式一致性机制完成状态同步和选主，降低单管理节点故障对平台控制面的影响。

- **数据平面 HA**：分布式存储的多副本机制确保数据在物理磁盘或节点损坏时依然可读可写。

- **业务实例 HA**：当物理节点发生故障时，平台可检测受影响虚拟机并在其他健康节点上重启。实际恢复时间取决于虚拟机规模、存储状态、网络条件和业务自身启动时间。

- **边缘自治**：边缘节点在中心链路异常时，可在已下发策略和本地资源范围内继续运行本地业务；策略变更、跨站点调度和全局审计汇聚需在链路恢复后同步。

## 5.2 企业级备份与容灾

平台提供备份管理能力，支持将虚拟机镜像备份至本地或远端存储。备份与恢复策略应结合业务等级、数据量、链路带宽和合规要求设计。

- **多协议支持**：支持备份至 NFS 存储或 S3 兼容对象存储，实现数据异地归档。

- **可用区容灾**：支持跨可用区的数据级与业务级容灾。RPO/RTO 指标与网络、存储复制方式、业务架构和容灾演练成熟度相关。

- **灵活策略**：支持 Cron 表达式级别的定时备份策略，满足 RPO/RTO 的严格要求。

- **多样化恢复模式**：支持原机覆盖恢复、异机重建恢复及文件级细粒度恢复。

- **边缘备份**：边缘站点可根据带宽条件选择本地备份、区域汇聚备份或远端归档。低带宽链路下应配套限速、窗口期和断点续传等项目策略。

## 5.3 混合架构与一云多芯

Cloudmap 具备强大的硬件异构兼容性，支持在单一集群内实现不同架构服务器的混合部署与协同管理。

- **异构资源池化**：支持将 x86、ARM、LoongArch 等不同架构的服务器构建为统一的资源池，上层应用感知不到底层差异。

- **国产化替代**：支持在原有资源池中纳入国产化节点，结合迁移、备份、验证和割接流程逐步替换老旧硬件。跨架构迁移涉及操作系统、驱动、应用兼容性和数据一致性校验，需按项目计划实施。
