# 10. 风险与合规

融合边缘云将资源从中心机房扩展到区域和边缘现场，带来更高的业务就近处理能力，也带来分布式运维、数据边界、网络链路和安全策略一致性的挑战。本章从建设和运营角度说明主要风险及控制建议。

## 10.1 数据安全与数据驻留

边缘云场景中的数据可能包含视频流、设备数据、业务日志、模型交互记录和个人信息。项目应在建设初期明确数据分类分级、留存位置、访问范围、备份周期和跨域传输规则。

- **本地处理**：对数据不能出园区、不能出域或对低时延有要求的业务，应优先在边缘节点或区域资源池完成处理。
- **最小权限**：租户、组织、角色和 API 权限应按职责划分，避免运维账号、业务账号和审计账号混用。
- **审计留痕**：关键操作、远程访问、策略变更、备份恢复和安全事件应记录审计日志，并规划留存周期。
- **传输保护**：跨站点数据同步、远程运维和备份链路应结合专线、VPN、证书、加密和访问控制策略设计。

## 10.2 网络与边缘节点风险

边缘节点通常部署在园区、工厂、门店或交通站点，现场网络条件、机房环境和运维能力差异较大。项目应避免简单套用中心机房模型。

- **链路风险**：中心与边缘之间可能出现丢包、抖动或中断，应规划边缘自治、日志缓存、断点续传和告警补传机制。
- **地址规划风险**：多站点网络容易出现地址冲突、路由绕行和安全域边界不清，应在实施前统一规划 VPC、扁平网络、公共子网和管理网段。
- **物理环境风险**：边缘站点需关注供电、散热、防尘、机柜空间、网络接入和现场巡检条件。
- **远程运维风险**：远程登录、控制台访问和应急操作应通过堡垒、权限审批和审计留痕约束。

## 10.3 分布式架构运营风险

融合边缘云的价值在于规模化复制，但规模化也会放大版本、配置、镜像、模型和策略不一致的问题。

- **版本一致性**：中心、区域和边缘组件应建立版本基线，升级前完成兼容性验证和回退预案。
- **配置漂移**：网络、安全、镜像、模板和备份策略应集中管理，减少现场手工修改导致的漂移。
- **容量风险**：边缘节点容量通常有限，应设置 CPU、内存、存储、GPU 和备份空间阈值，避免本地资源耗尽影响业务。
- **演练机制**：高可用、备份恢复、边缘断链、中心不可达和安全事件处置应纳入周期性演练。

## 10.4 合规边界说明

Cloudmap 提供身份权限、网络隔离、日志审计、国密适配、等保相关集成和安全服务编排能力。最终合规结果取决于客户制度、业务流程、第三方安全产品、测评范围和项目实施质量。涉及网络安全法、数据安全法、个人信息保护法、等保和行业监管要求时，应由客户、实施方和安全测评机构共同确认建设边界。
