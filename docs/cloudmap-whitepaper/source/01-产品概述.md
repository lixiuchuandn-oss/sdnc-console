# 1. 产品概述

## 1.1 产业背景

政企、制造、交通、园区、能源等行业正在从集中式信息化系统，转向“中心数据中心 + 区域资源池 + 现场边缘节点”的分布式数字基础设施。视频分析、工业质检、云桌面、数据库、容器应用、边缘推理等业务既需要中心侧统一治理，也需要在本地就近处理数据、降低链路依赖并满足数据驻留要求。

传统私有云和单点超融合系统解决了数据中心内部的资源池化问题，但在多站点统一纳管、边缘节点轻量交付、云边协同运维、异构算力调度、安全合规一致性等方面仍存在断点。单一边缘计算方案通常侧重现场计算，缺少统一云管、租户、网络、安全、备份和审计能力，难以支撑规模化复制。

融合边缘云的建设目标，是在保留中心云统一管理能力的同时，将计算、存储、网络、安全和运维能力下沉到区域和边缘侧，使分布式节点能够被统一规划、统一交付、统一监控，并在必要时具备本地自治能力。

## 1.2 产品定位

Cloudmap 融合边缘云由 Cloudmap OS 与 ComputerTower 管理平台组成，面向私有化、行业云和边缘云场景提供统一的云基础设施软件。平台以超融合资源池为基础，将虚拟机、容器、裸金属、云桌面、云盘、网络、安全、备份、数据库、智算推理等能力纳入同一管理体系，支持从单节点边缘站点到多可用区资源池的分级部署。

Cloudmap OS 负责资源池底层能力，包括计算虚拟化、云原生容器、分布式存储、虚拟网络、硬件直通和基础安全能力。ComputerTower 提供统一 Web 管理、租户与权限、资源编排、监控告警、审计、云资源纳管和多站点运维入口。二者共同支撑中心云、区域云与边缘节点的一体化建设。

本白皮书围绕融合边缘云建设展开，重点说明 Cloudmap 如何在不改变既有核心技术体系的基础上，支撑资源融合、云边协同、边缘自治、统一安全、智能运维与行业场景落地。

## 1.3 核心价值

### 1.3.1 资源融合

Cloudmap 将计算、存储、网络和安全能力部署在标准服务器资源池上，支持超融合与存算分离两类形态。用户可在同一平台交付云主机、容器、裸金属、云桌面、云盘、负载均衡、VPC 和安全服务，减少多套系统之间的重复建设与运维割裂。

### 1.3.2 云边协同

平台支持中心侧统一管理和边缘侧就近运行。中心侧负责策略、镜像、模型、租户、监控和审计，边缘节点负责本地业务承载、数据处理和现场运维。该模式适用于园区、工厂、门店、交通站点等对低时延、数据驻留和弱网连续性有要求的场景。

### 1.3.3 弹性部署

Cloudmap 支持从单节点、三节点轻量资源池起步，也可扩展到较大规模的数据中心资源池。不同站点可按业务负载选择通用计算型、高性能计算型、GPU/AI 推理型或存储增强型硬件，形成可分期建设、可横向扩展的资源体系。

### 1.3.4 兼容与可控

平台兼容 x86、ARM、LoongArch 等多种服务器架构，可对接国产化操作系统、第三方存储和安全设备，并通过 RBAC、审计、国密、等保相关安全能力支撑政企和行业合规建设。涉及选配组件或项目化集成的能力，在后续章节中按交付边界说明。
