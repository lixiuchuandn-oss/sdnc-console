# 权限管控 - 总体设计（PRD）

## 1. 概述

权限管控子系统负责平台内所有“谁可以对哪些资源执行哪些操作”的统一建模与实现，核心由三层构成：

- 权限原子（Action）：最小权限单元，对应某类资源上的某类操作。
- 权限策略（Policy）：一组权限原子的集合，可按分组与条件进行管理。
- 角色（Role）：权限载体，将策略或权限原子授予用户、租户或子账号。

本文件作为总览文档，给出整体模型与模块划分；各子模块的详细需求在各自 PRD 中说明。

## 2. 模型与关系

- Action：
  - 字符串标识，形如 `<资源前缀>.<子域...>:<动词>`。
  - 按平台（CNMC/SDNCC/CNSOC）和分组（租户管理、资源控制台、权限管控等）聚合。
  - 与后端 API 绑定，用于前后端统一鉴权。
- Policy：
  - 由若干 Action 组成，可附加条件（如租户、组织、标签等）。
  - 分为系统策略与自定义策略：
    - 系统策略由系统基于分组与读写规则自动生成。
    - 自定义策略由管理员按需配置。
- Role：
  - 承载一组 Policy 或 Action。
  - 可分 scope：系统级、租户级等。
  - 可为用户、租户子账号分配多个角色。

关系链路：**用户/租户子账号 → 角色 → 策略 → 权限原子 → API 调用能力**。

## 3. 子模块划分

- 权限原子（Action）管理：
  - 提供统一的权限原子目录与查询界面。
  - 自动从后端路由扫描已绑定的 Action。
  - 支持按平台、分组、功能筛选。
- 权限策略（Policy）管理：
  - 提供系统策略与自定义策略的创建、查看、编辑能力。
  - 支持基于 Action 选择和条件组合。
- 角色（Role）管理：
  - 提供角色的创建、编辑、启停。
  - 支持将策略与角色关联，并为用户/租户分配角色。
  - 支持“三权分立”预置角色。

本阶段优先落地“权限原子（Action）管理”和“角色对 Action 的聚合”，策略条件可后续迭代。

## 4. 与其他模块的关系

- 与多云管理（CNMC）：
  - 为租户管理、云资源池管理、租户专线等功能提供访问控制基础。
  - 统一抽象为 `tenants.*`、`clouds.*` 等 Action 前缀。
- 与 SDN 管理（SDNCC）：
  - 为安全域、隧道、服务链等提供读写粒度的权限控制。
- 与 AI SOC 中心（CNSOC）：
  - 为态势中心、威胁分析、报告等提供只读/管理权限。

各业务 PRD 在定义接口和页面时应显式声明所依赖的 Action，以便在权限管控模块中统一呈现与管理。
