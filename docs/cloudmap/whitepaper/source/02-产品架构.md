# 2. 产品架构

## 2.1 总体架构设计

Cloudmap 融合边缘云采用“中心统一管控、区域分级承载、边缘就近处理”的架构。中心云负责统一门户、租户、权限、镜像、策略、监控、审计和全局资源视图；区域云面向城市、园区或行业区域承载资源池和区域级运维；边缘节点部署在业务现场，承担本地计算、数据处理、云桌面、容器应用或 AI 推理等任务。

![Cloudmap 总体架构](assets/architecture.png)

**图 2-1 Cloudmap 总体架构**

- **Cloudmap OS**：提供软件定义计算、存储、网络和基础安全能力，支持虚拟机、容器、裸金属、云桌面、GPU/vGPU、分布式存储、VPC、扁平网络、负载均衡、安全组和备份等资源。
- **ComputerTower**：提供统一管理入口，覆盖资源池纳管、租户 IaaS 服务、运维监控、告警、审计、云安全中心、云桌面网关、数据库和 MaaS/AI 推理等选配服务。
- **中心-区域-边缘协同**：中心侧下发策略与模板，区域侧承载资源与运维职责，边缘侧就近运行负载并回传监控、告警和审计数据。弱网或中心链路异常时，边缘节点在既有策略下维持本地业务运行。
- **交付路径**：按场景选择 1 节点、3 节点或多节点资源池，完成硬件集成、Cloudmap OS 部署、ComputerTower 纳管和业务资源编排；存量服务器、第三方存储、安全设备可按项目边界接入。

## 2.2 分层架构

Cloudmap 的能力分为六层，分别对应硬件资源、资源虚拟化、云服务、云边协同、运维运营和安全合规。

1. **硬件与站点层**：支持中心机房、托管机房、区域机房、园区机房和边缘站点；硬件可按通用计算、高性能计算、GPU 推理、存储增强等类型规划。
2. **资源融合层**：由 Cloudmap OS 池化 CPU、内存、GPU、磁盘、网络和安全资源，提供超融合或存算分离部署形态。
3. **基础云服务层**：提供云主机、容器、裸金属、云桌面、云盘、镜像、快照、备份、VPC、负载均衡、安全组等 IaaS 能力。
4. **云边协同层**：统一管理多可用区、多资源池和边缘节点，支撑镜像/模型分发、策略同步、监控汇聚、告警上报和边缘自治。
5. **运维运营层**：提供资源大盘、巡检、容量分析、日志审计、租户权限、配额和服务目录，减少跨站点运维复杂度。
6. **安全合规层**：覆盖身份权限、网络隔离、流量编排、主机与边界安全、日志审计、国密适配、等保相关能力和数据驻留要求。

![Cloudmap 功能全景图](assets/function-map.png)

**图 2-2 Cloudmap 功能全景图**

功能全景图展示 Cloudmap 从资源池到业务服务的完整交付范围。底层算力集群兼容 x86、ARM、LoongArch 等服务器架构，可组成边缘轻量资源池、区域资源池或中心数据中心集群。云计算服务在其上提供计算、存储、网络和安全虚拟化，并扩展备份、对象/文件存储、SD-WAN、虚拟路由、云桌面和数据库等能力。

IaaS 服务面向单租户或多租户场景提供云主机、裸金属、容器、云桌面、云盘、VPC、负载均衡等基础资源，通过配额、权限和组织管理适配多部门使用。高级服务可按需叠加 PaaS 中间件、MaaS/AI 推理和云安全中心，与基础资源同平台交付。安全服务覆盖主机、边界、加密、堡垒、审计和安全流量编排，等保与国密能力按项目合规要求选配。

## 2.4 与传统架构的差异

与传统公有云相比，Cloudmap 更强调私有化部署、数据本地驻留、硬件自主规划和行业现场适配；与传统私有云相比，Cloudmap 将边缘节点和区域资源池纳入统一云管，减少多站点运维断点；与单一边缘计算平台相比，Cloudmap 不只提供现场计算，还提供租户、网络、存储、备份、安全、审计和统一运维能力，适合规模化建设和复制。
