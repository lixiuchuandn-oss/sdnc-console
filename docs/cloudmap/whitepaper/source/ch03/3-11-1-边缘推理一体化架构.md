### 3.11.1 边缘推理一体化架构

- **平台统一管控**：边缘推理算力以独立资源池或边缘节点形式接入 Cloudmap。运维人员在 ComputerTower 中完成资源入网、连通性校验、接口密钥配置、权限分配和监控接入，无需逐一登录现场节点维护。

- **资源复用**：智算模块复用 Cloudmap 既有底层能力，包括 GPU/vGPU 硬件直通、显存切分、NUMA 亲和调度和高性能分布式存储等（详见 **3.2**、**3.3.2**）。模型权重、缓存数据和推理实例可部署在本地资源池，减少重复建设。

- **分级部署**：中心侧维护模型目录、镜像模板、权限策略和监控视图；区域或边缘侧承载推理实例，就近处理业务请求。对带宽受限或数据不能离场的项目，推理请求和业务数据可在本地闭环处理，仅回传必要的运行指标和审计信息。

- **横向扩展**：除单机一体机外，推理集群支持多 Worker 节点扩展。调度模块感知各节点 GPU 负载并分发模型实例，满足从单点边缘到多节点智算资源池的扩容需求。

- **应用集成部署**：边缘推理集群以推理调度模块作为控制核心，应用编排服务通过反向代理对外提供访问，监控组件采集 GPU、模型实例和集群运行指标，形成推理调度、应用接入和运行监控一体化交付模式。

- **标准化接口**：推理服务兼容行业通用大模型 API 规范。现有业务系统、自研 AI 应用和第三方智能框架可通过标准接口接入，支持流式输出、工具函数调用和多模态交互；具体模型类型、上下文长度和并发能力以项目选型与硬件配置为准。
