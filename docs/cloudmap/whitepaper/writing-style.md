# Cloudmap 融合边缘云白皮书 · 写作约束

面向 **甲方采购、运维、项目负责人、行业方案负责人**。全文严格遵守以下规则。

## 1. 文风

- 政企产品白皮书 **务实写法**。
- 去掉 AI 式空洞修饰、浮夸话术、行业黑话、冗余形容词。
- **禁用**（含变体）：赋能、生态、底座闭环、极致、革新、引领、划时代、最佳、秒级、零丢失、零中断、开箱即用（无依据时）等虚话或绝对化表达。

## 2. 语言

- 读者：运维、采购、普通项目负责人；不要求读懂内核/控制器实现。
- 技术原理 **通俗化**；少生僻缩写；必须用缩写时 **括号解释一次**。
- **一句话能说清不写三句**。

## 2.1 术语口径

| 术语       | 统一写法                                                                   |
| ---------- | -------------------------------------------------------------------------- |
| 融合边缘云 | 中心云、区域云与边缘节点统一纳管、分级部署、协同调度的私有化云基础设施形态 |
| 中心云     | 承载统一管理、策略、监控、镜像、模型、租户与审计的中心侧平台               |
| 区域云     | 面向城市、园区、行业区域的中间层资源池，承担区域自治与就近调度             |
| 边缘节点   | 部署在园区、工厂、门店、交通站点等现场的轻量资源池                         |
| 云边协同   | 策略、镜像、模型、监控、告警与资源调度在中心侧和边缘侧之间的协同           |
| 边缘自治   | 中心链路异常时，边缘侧在既有策略下维持本地业务运行与基础运维               |

## 3. 内容结构（每条功能）

下表是**写作检查清单**，不是强制排版模板。每条功能在落笔前自问这四点是否答清；**不要求**把它们拆成四个固定加粗小标题或四段文字。

| 要素     | 说明                                                 |
| -------- | ---------------------------------------------------- |
| **实现** | 用户能做什么                                         |
| **机制** | 平台靠什么做到（通俗、可验证）                       |
| **价值** | 采购/项目/运维得到的实际好处                         |
| **边界** | 选配、规划、需项目部署或需外部系统配合的内容必须说明 |

落地要求：

- **能一行讲清就别拆成四段**。优先用「**加粗能力词** + 一句具体说明」的列表项，一行内同时带出实现、机制与价值（如 3.2.2、3.3.2 的写法）。
- **不为凑格式注水**：某条功能没有独立"机制"或"边界"时，就不写，**不得**为补全四要素而堆砌空话或虚构机制。
- **「边界」是硬性项**：凡选配、规划、需项目部署或需外部系统配合的能力，必须按 **§4** 标注（如「选配」「需单独部署」），这是四要素中最不能省的一项。
- 只写 **落地功能与实际价值**，不堆砌技术名词。

## 4. 禁用与边界

- 无意义长难句、成套行业话术、超前概念吹嘘。
- **不虚构**产品优势；与私有化超融合 **真实可交付** 能力一致。
- 规划中的能力须标注 **「规划」** 或 **「需单独部署」**，不得写为已上线。

## 5. 排版（Markdown）

- **一节一文件**（第 3 章在 `source/ch03/`）。
- 章：`#`；节：`##`；小节：`###`。
- **章节标题禁止**全角 `（）`、半角 `()` 及括号内一切补充说明；型号、缩写、范围等写在正文，不缀在标题后。
- 标题统一为 **`编号 + 名词短语`**，同级结构平行（如均用「迁移」「服务」「管理」收束，不混用「概要」「简版」等括号替代词）。
- 段落短；列表用 `-`；避免整屏密集文字。
- 图片：**优先 URL**；图注写在图片下一行斜体或说明段。
- **表格与图不得相邻**：Markdown 表格与配图（含紧随其后的图注行）之间、配图与表格之间，须**至少隔一段正文**；禁止表格结束下一行直接接 `![...]`，或图注下一行直接接表格。

## Markdown 示例

```markdown
## 3.4 网络服务

实现：虚拟机、容器接入虚拟网络并访问公网。  
能力：扁平网、VPC、负载均衡、地址转换、DNS、跨机房隧道。  
价值：网络在界面配置，减少改物理交换机。

### 3.4.1 公共子网

**实现目标**：提供南北向互通网段，支撑 EIP、NAT 等边界能力。  
**部署位置**：节点侧虚拟网络服务，在 3.1.3 业务网上供给（图 3-9）。  
**整体价值**：扁平子网、VPC 网络经边界服务关联公共子网即可对外互通。

![存储与网络关系示意](https://example.com/diagrams/cloudmap-net-storage.png)
```

> 上例的「实现/能力/价值」分行与「**加粗标签**分段」均为**可选写法之一**；多数小节用「**加粗能力词** + 一句说明」的列表即可，无需照抄四要素标签。
