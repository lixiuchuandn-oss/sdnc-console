# Cloudmap 使用手册 · 写作约束

面向 **运维人员、租户管理员、实施工程师**。与《技术白皮书》分工如下：

| 文档     | 写什么                       | 不写什么                 |
| -------- | ---------------------------- | ------------------------ |
| 白皮书   | 能力、架构、价值、部署形态   | 逐步点击路径、界面字段名 |
| 使用手册 | 菜单路径、操作步骤、注意事项 | 采购话术、架构长论述     |

## 1. 文风

- 第二人称或祈使句：**「进入…」「单击…」「在…中选择」**。
- 短句、编号步骤；一步一事。
- 与白皮书一致：**不虚构**未交付能力；规划项标注 **「规划」** 或 **「选配」**。

## 2. 每条操作说明结构

| 要素         | 说明                                        |
| ------------ | ------------------------------------------- |
| **适用角色** | 管理员 / 租户用户 / 需写权限                |
| **入口**     | 顶栏平台 → 侧栏 → Tab（与现网中文菜单一致） |
| **前置条件** | 资源池已接入、项目已分配、节点 Ready 等     |
| **步骤**     | 1. 2. 3. …                                  |
| **结果**     | 列表出现、状态变更、任务完成                |
| **注意**     | 互斥项、须重启等业务约束；不写 RBAC 通则 |
| **参见**     | 白皮书章节号；权限原子见 **第 4 章** / `cloudmap-pool-rbac.md` |

## 3. 界面路径写法

- **`source/` 下正文会导出为 Word 外发用户**：只写文档名、章节号、控制台菜单路径；**禁止** 写仓库路径（如 `docs/cloudmap/…`、`user-manual/…`）、源码路径（如 `pages/`、`.ts`）、维护文件（`COVERAGE.md`、`manifest.txt`）。维护说明写在 `writing-style.md`、`README.md` 等 **不进入 manifest** 的文件。
- 用 **`>`** 连接：`多云管理 > 资源池管理 > 某 Cloudmap 池 > 计算 > 虚拟机`。
- 按钮、Tab、字段名与 **控制台中文文案** 一致；**禁止** 在正文写 URL 路由（如 `resource_hub/datacenter_topology`）、前端组件名（如 React Flow、CodeMirror）、内部服务缩写（如 HMS），除非与界面原文完全一致且用户可见。
- **入口/Tab** 只写侧栏中文路径：`资源总览 > 机房拓扑`，不写括号里的 path。
- **权限原子** 只在 **第 4 章** 与 `docs/cloudmap-pool-rbac.md` 维护；功能节不写权限清单。
- **不写控制台通则**：如「无 write 时按钮隐藏、非置灰」「无权限 Tab 不显示」等 RBAC 默认行为，视为读者已知，**全文不提**。

## 4. 功能聚焦

**一类机制只在一处写全**；各功能操作节只写步骤与界面，用 **参见** 指向权威章，**禁止** 在各节里零星重复同一套说明。

| 主题 | 权威位置 | 功能节（第 2、3 章等）写法 |
| ---- | -------- | -------------------------- |
| **权限原子**、池内 Tab 与 read/write 对照 | **第 4 章**、`docs/cloudmap-pool-rbac.md` | **适用角色** 写角色名；**不列举** `clouds.xxx:write`；**不写** 无 write 时按钮是否显示 |
| **License / 功能授权** | **第 4 章 §4.5** | 只写「须多云管理授权」等结论，不展开 Feature 列表 |
| **名词与控制台约定** | **第 1 章 §1.3**、**第 7 章** | 正文直接用术语，不另起段落释义 |
| **能力、架构、部署形态** | **技术白皮书** | **参见白皮书 X.X** 一句带过 |
| **资源池功能目录** | **第 3 章**、`COVERAGE.md` | 按资源池菜单组织，不另设 `3.0` 索引 |

**禁止**：在 3.x 各节粘贴权限树片段、重复解释 RBAC 模型、描述无 write 时控件隐藏/置灰等通则、为单个按钮单独展开权限原子定义（除非该文件即该主题的唯一定稿节）、**X.0 操作总览 / 六步一览 / 专章路由表**（见 §5）。

## 5. 不写总览节

用户按 **Word 目录** 直达功能节，不读「操作总览」「分类介绍」类铺垫。

| 禁止 | 改法 |
| ---- | ---- |
| `X.0 列表页操作总览`、创建向导步骤总表、子节摘要路由大表 | 删掉；截图与步骤并入对应 **3.x.y** 专节 |
| 父节文件内按分类复述各子节（如原整篇 `3-4-网络服务.md`） | 父节仅保留 `## 标题` + **参见白皮书** 一行 |
| `3.0` 全 Tab 索引等维护对照 | 删除；资源池功能以第 3 章目录为准 |

**允许**：章标题下一句 **主入口**；节内 **参见 3.x.y** 一句交叉引用（不展开步骤）。

## 6. 白皮书对照

使用手册第 3 章按 Cloudmap 资源池菜单组织；手册不复制白皮书整段，只写 **怎么做**。

## 7. 排版

- 一节一文件，目录 `source/ch03/`（相对本手册 `user-manual/`）。
- 章 `#`、节 `##`、小节 `###`。
- **章节标题禁止**使用全角 `（）` 或半角 `()` 及其中补充说明；限定语写入正文首句，不写在标题里。
- 带编号的节标题统一为 **`X.Y 名词短语`**（如 `### 3.8.1 P2V 迁移`）；同一文件内操作小节可用 **`一、` `二、`** 或 **`操作名称`**，层级用 `#` 深度区分，不混用 `（1）` 式编号。
- 截图放在 `source/assets/`（可按模块分子目录），Markdown 使用 `![](assets/xxx.png)`。
- 截图清单与重跑命令见 [SCREENSHOTS.md](SCREENSHOTS.md)；白皮书对照见 [COVERAGE.md](COVERAGE.md)。

```markdown
**前置条件**：

**结果**：…

**注意**：…

**参见**：白皮书 3.x.x
```
