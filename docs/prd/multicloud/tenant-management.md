# 多云管理 - 租户管理 需求设计（PRD）

## 1. 概述

租户管理负责在多云环境中统一管理“租户 - 组织 - 资源”的关系，是安全域、SASE 网关、云资源池等能力的上层逻辑入口。通过租户管理，平台能够：

- 为不同业务方/客户/内部系统提供逻辑隔离的租户空间。
- 在租户内部以“组织（Org）”维度管理资源（项目/部门/环境/Namespace）。
- 将云资源池（Cloud）、VPC、VR、Harvester Namespace 等资源分配给具体组织。
- 为安全域、级联通道、SASE 网关等能力提供清晰的归属与权限边界。

本 PRD 重点定义：

- 租户与组织的基础模型。
- 云资源池与组织的分配关系。
- 前端的租户管理页面与主要交互。
- 对其他模块（安全域、SASE 网关、多云控制台）的影响。

## 2. 核心概念

### 2.1 租户（Tenant）

- 描述：平台上的逻辑隔离单元，对应一个业务方、客户或内部系统。
- 来源：
  - 从 IAM/统一身份系统同步，或
  - 在平台中由超级管理员创建。
- 关键属性：
  - `tenantId`：唯一标识。
  - `name`：租户名称。
  - `type`：企业租户/项目租户/Lab 等分类（可选）。
  - `owner`：租户负责人（用户或用户组）。

### 2.2 组织（Org）

- 描述：租户内部的资源组织单元，可对应实际组织结构（部门/项目组/环境），或对应基础设施侧的项目命名空间。
- 关系：
  - 一个租户包含多个组织。
  - 每个组织只属于一个租户。
- 典型映射：
  - 公有云：Org ≈ 当前租户下的项目/Resource Group/Folder。
  - Harvester：Org ≈ Namespace。
- 关键属性：
  - `orgId`：唯一标识。
  - `tenantId`：所属租户。
  - `name`：组织名称（如：安全事业部-生产-SAAS）。
  - `code`：组织编码（如：sec-prod-saas）。
  - `kind`：逻辑类型（部门/项目/环境/命名空间）。

### 2.3 云资源池与资源归属

结合《租户-组织-资源 模型 PRD》（[TenantOrgResource.md](file:///d:/ComputeTower/Compute.Tower/prd/design/TenantOrgResource.md)）：

- 云资源池（Cloud）：
  - 平台级资源，不直接挂 `tenantId`。
    - 阿里公有云 通过ak/sk 认证，获取的资源是单租户下的所有资源。
    - 华为公有云 通过ak/sk 认证，获取的资源是单租户下的所有资源。
    - Cloudmap私有云/Cloudmap融合边缘云/Harvester，通过admin令牌接入，可提供多namespace，每个namespace可对应某租户下的一个组织。
  - 通过 `ResourcePoolAssignment(organizationId, cloudId)` 将某个 Cloud 分配给一个或多个组织。
- 资源归属：
  - 网络资源：VPC、VR、子网、SRv6 隧道、IPsecVPN 等。
  - 计算资源：各云账号或集群下的计算与运行环境，例如阿里云/华为云下的 VM、容器集群，以及 Cloudmap 私有云/融合边缘云/Harvester 集群中的 Namespace、VM 等；其中每个 Namespace 可映射为某租户下的一个组织。
  - 安全资源：安全域、安全服务、服务链、引流策略等。
  - 以上资源在平台层都通过 `tenantId + orgId` 映射到租户与组织。

## 3. 用户与权限

- 超级管理员：
  - 创建/删除租户。
  - 为租户指定负责人（owner）。
  - 为租户初始化组织结构。
- 租户管理员（租户 owner 或被授予等效权限的用户）：
  - 管理本租户下的组织。
  - 为组织分配云资源池。
  - 管理组织内的安全域、SASE 网关等资源的归属。
- 安全运维/网络管理员：
  - 在授权范围内对某个租户/组织内的资源进行配置与运维。

## 4. 功能范围

### 4.1 租户列表

- 列表字段：
  - 租户名称、tenantId。
  - 类型（企业/项目/Lab 等）。
  - 负责人（owner）。
  - 组织数量。
  - 关联云资源池数量。
- 支持操作：
  - 创建租户。
  - 编辑租户信息。
  - 查看详情。
  - （受限）删除租户。

### 4.2 租户详情

- 结构建议：
  - 基本信息卡片：名称、tenantId、类型、负责人。
  - Tab1：组织管理。
  - Tab2：云资源池分配。
  - Tab3：租户下资源总览（安全域、SASE 网关、VPC 数量等汇总）。

## 5. 组织管理（Org 管理）

### 5.1 组织列表与结构

- 在租户详情中展示组织列表或组织树：
  - 字段：orgId、name、code、kind、描述。
  - 可选支持层级结构（父子组织），但初版可先使用平面列表。
- 支持操作：
  - 新建组织。
  - 编辑组织信息。
  - 禁用/启用组织（避免误删）。

### 5.2 新建组织

- 表单字段：
  - `name`（必填）：组织名称。
  - `code`（必填，唯一）：组织编码。
  - `kind`（可选）：部门/项目/环境/命名空间。
  - 描述（可选）。
- 校验：
  - 同一租户下 `code` 不可重复。
  - `name` 不可为空，长度限制。

### 5.3 组织与资源视图联动

- 在组织列表中支持查看：
  - 当前组织下的安全域数量。
  - 当前组织下的 SASE 网关数量。
  - 当前组织下的云资源池数量。
- 通过点击可跳转到对应模块（安全域管理、SASE 网关、云控制台），并自动带上租户/组织过滤条件。

## 6. 云资源池分配

### 6.1 资源池列表

- 在租户详情的“云资源池分配”Tab 中：
  - 左侧：平台所有可分配的 Cloud 列表（未分配或可多租户共享资源池）。
  - 右侧：当前租户下各组织已分配的 Cloud 列表。

### 6.2 分配流程

- 操作步骤示例：
  1. 选择组织（Org）。
  2. 在可用 Cloud 列表中勾选要分配的资源池。
  3. 点击“分配到组织”。
- 结果：
  - 创建 `ResourcePoolAssignment(organizationId, cloudId)` 记录。
  - 该 Cloud 将出现在对应组织下的云资源选择器中（例如：安全域创建向导中的“云资源池”下拉框）。

### 6.3 约束与回收

- 约束：
  - 同一个 Cloud 可分配给多个组织，用于共享资源池场景。
  - 若要取消某 Cloud 与组织的关联，需要检查该组织下是否仍有基于该 Cloud 创建的资源（VPC/VR 等），避免“悬空资源”。
- 回收：
  - 若强制取消关联，需在 UI 明确提示影响范围。

## 7. 与安全域 / SASE 网关的关系

### 7.1 安全域

- 创建安全域时：
  - 需在“租户 → 组织”上下文中进行（当前登录用户的租户/组织或显式选择）。
  - **资源筛选约束**：
    - **云资源池**：只能选择已分配给当前组织的云资源池（通过 `ResourcePoolAssignment` 关联）。
    - **VPC**：只能选择属于所选云资源池的 VPC。
    - **VR/网关**：只能选择属于当前组织（或其分配的云资源池）的 VR 实例。
  - 安全域实体挂 `tenantId`、`orgId`，后端接口需校验这些资源归属关系。
- 租户管理视角：
  - 在租户详情中可看到各组织下安全域的数量与状态，支持跳转到安全域管理页面。

### 7.2 SASE 网关（VR 实例）

- VR 实例在平台中通过 VR 配置表挂接 `tenantId`、`orgId`（对应后端 VRConfig 实体），即 VR / CSMctl / 安全域 的归属最终都会收敛到“租户-组织”维度。
- 本地 SASE 网关控制台登录时使用“租户主账号/授权账号”，平台在标准绑定流程中根据登录上下文确定 `tenantId` 与 `orgId`，并为该 VR 分配全局唯一 `vr_unique_id`：
  - VR 根据 `vr_unique_id` 向 CSMctl 注册、上报心跳。
  - 平台侧通过 CSMctl 北向接口按 `vr_unique_id` 拉取 VR 状态，并与 VR 配置表中的 `tenantId + orgId` 做归属对齐。
- 租户管理视角：
  - 在组织视图中展示该组织下所有 SASE 网关数量与健康状态概览（通过“VR 实例管理（含 SASE 子类型）”页面按 `tenantId + orgId` 过滤），并可按需跳转到 [SASE 网关 PRD](file:///d:/ComputeTower/Compute.Tower/docs/prd/sdn/sase-gateway.md) 中描述的接入/运维场景。

## 8. 前端页面与导航

### 8.1 路由建议

- 租户列表：`/admin/multicloud/tenants`
- 租户详情：`/admin/multicloud/tenants/:tenantId`
  - Tab：组织管理、云资源池分配、资源总览。

### 8.2 交互要求

- 统一在页面顶部固定展示当前“租户”上下文。
- 在组织级操作（分配资源池、查看资源）时，始终带上 `tenantId + orgId` 作为过滤条件。

## 9. 数据模型与接口（高层）

- Tenant：
  - `tenantId`、`name`、`type`、`owner`、`description`、`createdAt` 等。
- Org：
  - `orgId`、`tenantId`、`name`、`code`、`kind`、`description`。
- ResourcePoolAssignment：
  - `id`、`orgId`、`cloudId`、`createdAt`。

后端接口需提供：

- 租户 CRUD。
- 某租户下组织列表 CRUD。
- 某组织的云资源池分配管理接口。

## 10. 验收要点

- 能在平台中查看所有租户及其基本信息。
- 能在某租户下创建/管理组织，并保持 `tenantId + orgId` 关系一致。
- 能将云资源池分配给某个组织，并在安全域/云控制台等页面中按组织过滤资源。
- 安全域与 SASE 网关在创建/管理过程中，都能带上租户/组织上下文，并在租户视角下正确汇总。
