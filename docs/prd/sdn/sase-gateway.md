# SDN 管理 - SASE 网关 需求设计（PRD）

## 1. 概述

SASE 网关（下文统一称为 VR 实例）是安全域与云资源/物理网络之间的流量入口和策略执行点，用于：
- 承载跨地域互联（SRv6/IPsec 等隧道）。
- 将业务流量引流至安全资源池（安全域→安全服务）。
- 上报运行与安全状态，作为安全域健康的关键信号源。

本 PRD 主要覆盖：
- VR 实例的纳管能力（发现、绑定、配置）。
- VR 实例与租户账号的绑定流程。
- VR 实例的唯一 ID 体系、向 CSMctl 的注册与心跳。
- 平台侧对 VR 实例在线状态与安全域归属的管理。

## 2. 目标与非目标

### 2.1 目标
- 支持平台集中管理多云/多环境中的 SASE 网关（VR 实例），统一视图展示。
- 建立“VR 实例 ↔ 租户/组织 ↔ 安全域”的明确关系链路。
- 提供完备的 VR 生命周期管理：创建/绑定/配置/删除/状态监控。
- 实现从本地 VR 控制台登录，到平台识别归属，再到安全域构建的闭环。

### 2.2 非目标
- 不在本 PRD 中定义具体路由协议、IPsec、SRv6 等底层能力的详细参数（参考 VR 标准模式、SRv6/IPsec 专项 PRD）。
- 不覆盖各云厂商原生 VPN 网关的能力（属于多云 Provider 能力适配）。

## 3. 核心概念

- **VR 实例（SASE 网关）**：部署在物理机或虚拟机上的虚拟路由器实例，承载隧道/安全流量。
- **VR 唯一 ID（vr_unique_id）**：平台分配的全局唯一标识，用于跨平台、VR、本地配置、CSMctl 关联。
- **CSMctl**：集中安全管理控制平面，负责接收 VR 注册与心跳，维护真实运行状态。
- **安全域**：代表一块业务网络（IDC/VPC/办公等）的安全边界，VR 是其与安全资源池之间的入口。
- **安全资源池**：承载安全服务的资源集合（防火墙、WAF、IPS 等），通过隧道或直连方式连接至安全域。

## 4. 用户与角色

- 云平台管理员：全局查看与运维 VR 实例，配置租户/组织级的策略。
- 租户管理员（主账号）：在本租户下创建、绑定和管理 VR 实例。
- 安全运维人员：关注 VR 在线状态、告警与安全域关联。

## 5. 功能范围

### 5.1 VR 实例列表与详情

- VR 实例列表页面：
  - 显示字段：VR 实例 ID、名称、角色（CE/PE/Local/标准）、状态（ONLINE/OFFLINE/DEGRADED）、公网 IP、内网 IP、所属租户/组织、安全域数量、版本。
  - 支持按租户/组织、状态、角色、名称搜索与过滤。
- VR 实例详情（弹窗或详情页）：
  - 基本信息：ID、名称、角色、部署位置（资源池/宿主机）、版本。
  - 网络信息：公网口 IP、内网口 IP、接口列表（参考 VR 配置结构）。
  - 状态信息：当前 health_status、CPU/内存/会话数、最近心跳时间。
  - 关联信息：所属安全域、参与的 SRv6 隧道、IPsec VPN、级联通道、服务链等。

### 5.2 列表操作：添加 VR 实例（非标准操作）

- 正常流程下，VR 实例由基础设施团队在各资源池中独立部署，启动后通过心跳向 CSMctl 自注册；平台再通过 CSMctl 北向接口发现所有已注册的 VR 实例，并按 `vr_unique_id` 进行归属识别与展示。
- “添加 VR 实例”仅作为演示或排障使用的非常规入口，不改变上述标准流程：
  - 用途：
    - 在实验/演示环境中手工登记某个已存在的 VR 实例，便于在平台界面中快速查看与调试。
    - 在 CSMctl 已有记录但平台侧元数据缺失的情况下，辅助补齐平台侧 VR 资源信息。
  - 行为：
    - 支持录入 VR 的基础信息（名称、租户/组织、角色、公网/内网 IP 等），在平台侧创建一条 VR 资源记录。
    - 该记录最终仍需依赖 VR 自身向 CSMctl 注册并上报心跳，平台通过 `vr_unique_id` 与 CSMctl 数据对齐后，才视为“纳管完成”。

### 5.3 列表操作：角色设置向导

- 为选中的 VR 实例通过向导设定角色：
  - CE 角色：参考 `prd/page/interconnect/vr-CE.md`。
  - PE 角色：参考 `prd/page/interconnect/vr-PE公网口.md`、`vr-PE内网口.md`。
  - 标准角色：参考 `prd/page/interconnect/vr-标准.md`。
- 向导输出配置写入 VR 配置模板，并支持一键下发（调用 VR 配置编辑接口）。

### 5.4 列表操作：专家模式

- 专家模式用于高级运维或调试场景，支持：
  - 查询现有配置：调用 “VR 配置查询” 接口（`GET /V2/ctcontrol/VR2/VRConfig?uuid=<uuid>`）。
  - 配置模板编辑：基于 “VR 配置编辑” 样例，提供 JSON 结构级编辑界面。
  - JSON 预览与下发：前端根据表单拼接 JSON，调用 `POST /V2/ctcontrol/VR2/VRConfig` 完成配置更新。

### 5.5 列表操作：删除 VR 实例

- 支持删除 VR 实例资源记录，前置条件：
  - 未绑定关键安全域（或要求先从安全域解绑）。
  - 无正在运行的隧道或服务链依赖（或明确提示影响）。
- 删除时需弹出确认提示，说明影响范围。

## 6. VR 实例与租户账号绑定及注册上云

本节定义 SASE 网关在“VR 模式”下的标准接入流程：由 C 端用户在本地 SASE 网关控制台完成租户组织登录，平台下发 VR 唯一 ID，VR 向 CSMctl 自注册并上报心跳，平台再通过 CSMctl 北向接口发现并完成归属关联。

### 6.0 标准流程概览（SASE 模式）

1. 用户在 SASE 网关本地控制台使用平台租户组织主账号（或授权账号）登录。
2. 平台收到登录请求，完成认证并允许用户登录本地控制台。
3. 平台为该 VR SASE 网关生成唯一的 VR 标识（`vr_unique_id`/uuid），并下发给本地控制台。
4. 本地 SASE 网关控制台将 `vr_unique_id` 写入本地配置，网关开始根据该 ID 向 CSMctl 上报心跳。
5. CSMctl 接收心跳并记录该 SASE 网关的 `vr_unique_id` 及运行状态。
6. 平台通过 CSMctl 北向接口查询所有已注册的 VR 实例信息（含 `vr_unique_id` 列表及状态）。
7. 平台将第 1 步绑定的租户/组织信息与第 6 步从 CSMctl 获取的 `vr_unique_id` 记录进行匹配，从而完成“租户组织 ↔ CSMctl 中该 SASE 网关记录”的最终关联。

### 6.1 本地控制台登录（绑定租户组织主账号）

- 本地 SASE 网关（VR 实例）控制台不自建账号体系，用户需使用平台租户组织的主账号或具备 VR 管理权限的账号登录。
- 登录方式：
  - 推荐采用平台统一认证（SSO/OIDC，参考 `docs/design/sso.md`），本地控制台跳转平台认证后返回 token。
- 登录成功后，控制台可获得：
  - `tenant_id`、`org_id`
  - 登录用户 ID（租户主账号或授权账号）
  - 权限范围（是否允许绑定/解绑 VR 实例等）
- UI 要求：
  - 显示当前已绑定租户/组织信息。
  - 显示当前登录用户信息与权限提示。

### 6.2 获取并写入 VR 唯一 ID

- 本地控制台在用户成功登录后调用平台 API，请求为当前 VR 实例分配唯一 ID 并完成绑定：
-  - API：`POST /api/vr-config/bind`
-  - 请求体：
     - `tenant_id`、`org_id`（可从登录返回的 token 中解析，或显式传入）
     - 设备指纹：`device_fingerprint`（序列号、CPU ID 或证书公钥等）
     - VR 实例标识：`vm_id`（宿主系统中的实例 ID）、`vr_uuid`（若设备侧已有自生成 UUID 则可上传，否则留空）
     - 展示名称：`display_name`
- 平台行为：
  - 如请求中未提供 `vr_uuid`，平台自动生成全局唯一 `vr_unique_id` 作为该 VR 实例的主标识；
  - 将 `vr_unique_id` 与 `tenant_id/org_id`、设备指纹、`vm_id` 等信息一并写入 VR 资源表中；
  - 若传入的 `vr_uuid` 已存在，则以该值作为 `vr_unique_id` 进行绑定。
- 平台响应：
  - 返回字段：
    - `vr_unique_id`
    - `tenant_id`
    - `org_id`
    - `display_name`
    - `device_fingerprint`
    - `bind_status`（例如：`BOUND`）
- 本地控制台将 `vr_unique_id` 写入 VR 配置文件（例如 `/etc/vr/config.yaml`）中，作为后续向 CSMctl 注册与心跳上报的主标识。
- 前端提示：
  - 绑定成功：展示 `vr_unique_id` 片段及提示“可在云平台 VR 实例列表中查看该实例”。
  - 绑定失败：展示错误原因（权限不足/激活码无效/已绑定其他租户等）。

### 6.3 VR 实例向 CSMctl 注册与心跳上报

- VR 启动/重启流程（SASE 模式）：
  - 启动时读取配置中的 `vr_unique_id` 和设备证书/指纹。
  - 建立与 CSMctl 的安全连接（双向 TLS）。
  - 向 CSMctl 发起注册：
    - 携带字段：`vr_unique_id`、设备指纹、版本号、管理 IP 等。
  - 注册成功后，CSMctl 为该实例生成内部 ID（如 `csm_vr_id`），并标记为 `ONLINE`。
- 心跳上报：
  - 周期上报（例如 10–30s），内容涵盖：
    - `vr_unique_id`
    - 运行状态（CPU、内存、会话数）
    - 链路状态（隧道是否 UP）
  - CSMctl 根据心跳维护在线状态，超时后标记 `OFFLINE` 或 `TIMEOUT`。

### 6.4 平台从 CSMctl 识别 VR 归属

- 平台与 CSMctl 的数据同步：
  - 拉模式：平台定期调用 CSMctl，按时间戳增量获取 VR 状态。
  - 推模式：CSMctl 通过 Webhook 将 `VR_ONLINE/VR_OFFLINE/VR_DEGRADED` 事件推送到平台。
- 归属识别：
  - 平台按 `vr_unique_id` 在自身数据库中查找 VR 资源记录（这些记录来自第 6.2 步中“租户组织绑定”时创建的元数据）：
    - 找到：将该 CSMctl 记录与对应的租户/组织关联起来，并更新 VR 实例在线状态、心跳时间和健康指标。
    - 未找到：记录为“未识别 VR 实例”，用于异常排查或后续补绑。
- 从 VR 实例到安全域：
  - 平台通过 VR 实例关联其所在安全域（一个 VR 可参与多个安全域）。
  - 在安全域详情中显示该安全域所依赖的 VR 实例及其状态。

### 6.5 异常与安全要求（概览）

- 同一 `vr_unique_id` 在不同设备上同时出现：
  - CSMctl 检测到同 ID 不同设备指纹/IP 时标记冲突。
  - 平台拉取该状态后生成安全告警，可要求人工确认并暂停可疑实例。
- VR 解绑与重绑定：
  - 从一个租户解绑并绑定到另一个租户需更高权限与审批流程。
  - 解绑后 `vr_unique_id` 的处置策略需在设计中明确（保留/重置）。

## 9. 验收要点

- 能在云端平台中查看所有 VR 实例及其在线状态，并可按租户/状态过滤。
- 能通过本地 VR 控制台完成租户账号登录、VR 唯一 ID 获取与写入。
- VR 能正常向 CSMctl 注册和上报心跳，平台能据此识别 VR 归属与健康状态。
- 安全域详情中能准确展示关联的 VR 实例与其状态。
- 异常场景（ID 冲突、未识别实例）能在平台中清晰暴露，并产生相应告警提示。

## 10. 端到端场景：SASE 新租户接入

本节从“零状态”出发描述一个新租户接入 SASE 的端到端场景，串联“租户管理 → 云资源池 → 安全域 → SASE 网关 → 隧道与服务链”全流程。

### 10.1 场景前提

- 平台已完成基础部署，并接入至少一个云资源池（如阿里云账号、Cloudmap 私有云或 Harvester 集群）。
- 平台管理员具备创建租户、组织和分配云资源池的权限。
- 目标：为新租户 A 接入一条“总部 IDC ↔ 云上 VPC”的安全接入路径，通过 SASE 网关和安全域实现流量引流与策略控制。

### 10.2 步骤一：创建租户与组织

1. 平台管理员进入“多云管理 - 租户管理”：
   - 创建租户 A：填写名称、类型（企业租户）、负责人。
2. 在租户 A 详情页中：
   - 新建组织 `Org-A-prod`，kind=“环境/生产”，用于承载生产环境资源。
3. 在“云资源池分配”中：
   - 将已接入的云资源池（例如阿里云账号、Cloudmap 私有云）分配给组织 `Org-A-prod`。

结果：
- 租户 A 与组织 `Org-A-prod` 建立。
- `Org-A-prod` 下具备可使用的云资源池，用于后续创建 VPC 和 VR 实例。

### 10.3 步骤二：为租户创建安全域

1. 租户 A 的管理员登录平台，在“SDN 管理 - 安全域管理”中点击“新建安全域”。
2. Step 1（基础信息）：
   - 选择租户：A。
   - 选择组织：`Org-A-prod`。
   - 填写安全域名称：`A-HeadOffice-VPC`。
   - 类型：VPC。
3. Step 2（网络与引流方式）：
   - 选择云资源池：`Cloud-A`（已分配给 `Org-A-prod` 的阿里云资源池）。
   - VPC 选择：
     - 若租户已有 VPC：从列表中选取 `vpc-prod-a`。
     - 若需要新建：填写 VPC 名称与 IPv4 CIDR，并可选开启 IPv6。
   - VR 绑定：
     - 暂时选择“绑定已有 VR”，后续将在 SASE 网关模块中创建并绑定。
   - 引流方式：
     - 选择“隧道引流（tunnel）”，表示该安全域的流量需要通过 SASE 网关隧道进入安全资源池。
4. Step 3（确认）：
   - 检查基础信息/云资源/VPC/引流方式是否正确，点击“创建”。

结果：
- 安全域 `A-HeadOffice-VPC` 创建成功，绑定租户 A 与 `Org-A-prod`，引流方式为 `tunnel`。

### 10.4 步骤三：在资源池中部署 SASE 网关（VR 实例）

> 部署动作本身通常由基础设施/网络团队在各资源池中完成，不通过本平台发起，平台只负责“纳管”和“展示”。

1. 基础设施团队在资源池 `Cloud-A` 中按照标准流程部署一台 VR 实例（如在物理机/虚拟机/集群中安装 VR 软件，完成基础网络配置）。
2. 部署完成后，记录该实例的管理 IP/访问方式，并确保其能够访问 CSMctl 地址。
3. （可选，演示/排障场景）平台管理员在“SDN 管理 - SASE 网关”列表中使用“添加 VR 实例”：
   - 选择租户：A。
   - 选择组织：`Org-A-prod`。
   - 填写 VR 名称（如 `vr-a-hq`）、角色、公网/内网口信息等基础元数据，用于在平台中创建对应的 VR 资源记录。

结果：
- 资源池中已存在一台物理/虚拟 VR 实例，将作为租户 A 的 SASE 网关；平台侧可选地提前登记其元数据，等待后续通过 CSMctl 自注册信息完成归属对齐。

### 10.5 步骤四：本地 SASE 控制台登录与唯一 ID 绑定

1. 运维人员在 VR 实例部署完成后，通过其管理 IP 访问本地 VR 控制台。
2. 在本地控制台登录页面选择“使用平台账号登录”：
   - 输入租户 A 管理员（或授权账号）的凭据。
   - 经平台统一认证（SSO/OIDC）成功后返回 token。
3. 本地控制台调用平台绑定接口：
   - 上报 `tenant_id = A`、`org_id = Org-A-prod`、设备指纹（序列号/证书公钥）、VM 标识（vm_id/uuid）。
   - 平台为该 VR 实例生成全局唯一的 `vr_unique_id` 并返回。
4. 本地控制台将 `vr_unique_id` 写入 VR 配置文件中，并在 UI 中展示：
   - “已绑定租户：A / 组织：Org-A-prod”。
   - “平台 VR 资源：vr-a-hq（可在云端列表中查看）”。

结果：
- VR 实例 `vr-a-hq` 与租户 A / `Org-A-prod` 完成绑定，并拥有唯一 `vr_unique_id`。

### 10.6 步骤五：VR 向 CSMctl 注册并上报心跳

1. VR 重启或重新加载配置后：
   - 启动时读取 `vr_unique_id` 与证书/指纹。
   - 建立与 CSMctl 的双向 TLS 连接。
2. 向 CSMctl 发起注册：
   - 携带 `vr_unique_id`、设备指纹、版本号、管理 IP 等信息。
3. 注册成功后：
   - CSMctl 为其生成 `csm_vr_id`，状态标记为 `ONLINE`。
4. VR 周期性上报心跳与运行状态：
   - 内容包括 `vr_unique_id`、CPU/内存/会话数、隧道状态等。
   - 心跳异常或中断时，CSMctl 将状态标记为 `OFFLINE` 或 `DEGRADED`。

结果：
- 平台从 CSMctl 可以实时获取 `vr-a-hq` 的在线状态与运行指标。

### 10.7 步骤六：平台识别 VR 归属并关联到安全域

1. 平台定期/实时从 CSMctl 获取 VR 状态：
   - 使用 `vr_unique_id` 在自身数据库中查找 VR 资源。
2. 匹配成功：
   - 将 `vr-a-hq` 标记为 ONLINE，并更新其 health_status/心跳时间等信息。
   - 同时维护“VR 实例 ↔ 租户 A ↔ Org-A-prod”的映射。
3. 将 VR 关联到安全域：
   - 在安全域 `A-HeadOffice-VPC` 的配置中，将 `vr-a-hq` 作为该安全域的 SASE 出口。
   - 在安全域详情页中显示：
     - 绑定 VR 实例：`vr-a-hq`（状态 ONLINE）。
     - 引流方式：隧道引流（tunnel）。

结果：
- 平台可以在安全域视角下看到：`A-HeadOffice-VPC` 使用 `vr-a-hq` 作为隧道出口，且状态在线。

### 10.8 步骤七：创建隧道与服务链（可选扩展）

1. 在“跨地域互联/SRv6/IPsec VPN”模块：
   - 以 `vr-a-hq` 为一端，与云侧/总部侧对端 VR 建立 SRv6 或 IPsec 隧道。
   - 完成互通路由配置。
2. 在“服务链管理/安全服务编排”模块：
   - 基于安全域 `A-HeadOffice-VPC` 创建服务链：
     - 选择引流方式：默认继承安全域的 `trafficMode = tunnel`。
     - 挂载安全服务：防火墙、IPS/WAF 等。
3. 生效后：
   - 从租户 A 总部或 VPC 发出的业务流量，经 `vr-a-hq` 隧道进入安全资源池，按服务链顺序通过安全服务，再回到业务路径。

结果：
- 新租户 A 已完成从“租户 → 组织 → 云资源池 → 安全域 → SASE 网关 → 隧道 → 服务链”的完整接入路径。

### 10.9 关键校验与告警

- 租户/组织校验：
  - 安全域、VR 实例、VPC 必须共享相同的 `tenantId` 与 `orgId`。
- 状态告警：
  - 若 `vr-a-hq` 心跳超时，安全域 `A-HeadOffice-VPC` 应标记为“接入受影响”，并触发告警。
  - 若检测到相同 `vr_unique_id` 在其他设备上注册，应标记为“ID 冲突”，要求人工介入。
