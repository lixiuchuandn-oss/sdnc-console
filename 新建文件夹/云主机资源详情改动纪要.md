# 云主机资源详情改动纪要（Harvester VM Detail Drawer）

- 需求概述
  - 虚拟网卡：当网络类型解析为 “VPC / ovn-cluster / 子网” 时，展示为 “扁平子网/子网名”。
  - 节点调度：当节点亲和性包含 `network.harvesterhci.io/mgmt In true` 时，前端不展示该亲和性标签（过滤）；若过滤后无其它表达式，显示“未设置”。

- 涉及文件
  - [HarvesterVmDetailDrawer.tsx](file:///d:/work/Compute.Tower/frontend/src/pages/Clouds/Harvester/components/HarvesterVmDetailDrawer.tsx)

- 修改功能与效果
  - 网卡类型映射
    - 原行为：kube-ovn 网络以 “VPC / <VPC显示名> / <子网显示名>” 展示。
    - 新行为：当 VPC 为 `ovn-cluster` 时，展示为 “扁平子网/<子网显示名>”。其他 VPC 仍保持 “VPC / ... / ...”。
    - 影响：虚拟网卡列表的 “使用网络” 字段文案更符合扁平子网的认知，同时保留具体子网名称用于定位。
  - 节点亲和性过滤
    - 原行为：完整展示 `nodeAffinity.requiredDuringSchedulingIgnoredDuringExecution.nodeSelectorTerms.matchExpressions`。
    - 新行为：过滤掉 `key === 'network.harvesterhci.io/mgmt' && operator === 'In' && values 包含 'true'` 的表达式；若过滤后为空，显示“未设置”。
    - 影响：节点调度区不再展示 mgmt 亲和性，避免误导。

## 代码改动详情

### 1. SafeRead.interfaces：kube-ovn 网络类型映射为“扁平子网/子网名”

位置：Harvester VM 详情页网卡信息聚合逻辑（SafeRead.interfaces）

[HarvesterVmDetailDrawer.tsx](file:///d:/work/Compute.Tower/frontend/src/pages/Clouds/Harvester/components/HarvesterVmDetailDrawer.tsx#L858-L888)

```tsx
// 兼容 NAD config 的两种形态：plugins 列表或单对象
const plugins = config.plugins || [config];
const kubeOvnConfig = plugins.find((p: any) => p?.type === 'kube-ovn');
const bridgeConfig = plugins.find((p: any) => p?.type === 'bridge');

if (kubeOvnConfig) {
  // [VPC 网络] kube-ovn：用 subnet.spec.vpc 找到 VPC；子网/VPC 均优先 tower.io/alias
  const subnet =
    subnets.find((s: any) => {
      if (s.metadata?.name !== targetName) return false;
      const sns = s.metadata?.namespace || s.namespace;
      if (targetNs && sns) return sns === targetNs;
      return true;
    }) || subnets.find((s: any) => s.metadata?.name === targetName);
  if (subnet) {
    const vpcName = subnet.spec?.vpc || subnet.vpc || 'Unknown VPC';
    const vpc = vpcs.find((v: any) => v.metadata?.name === vpcName);
    const vpcDisplay = vpc?.metadata?.annotations?.['tower.io/alias'] || vpcName;
    const subnetAlias = String(subnet?.metadata?.annotations?.['tower.io/alias'] ?? '').trim();
    const subnetDisplay = subnetAlias || subnet.metadata?.name || targetName;
    if (String(vpcName) === 'ovn-cluster') {
      displayName = `扁平子网/${subnetDisplay}`;
    } else {
      displayName = `VPC / ${vpcDisplay} / ${subnetDisplay}`;
    }
  } else {
    // subnet 资源缺失时兜底展示
    displayName = `VPC / ${targetName}`;
  }
} else if (bridgeConfig) {
  // [Flat 网络] bridge：按 VLAN 与 NAD 名称展示
  const vlanId = bridgeConfig.vlan;
  displayName = `Flat / ${vlanId ? `VLAN ${vlanId} / ` : ''}${nad.metadata.name}`;
} else {
  // [其它网络] 自定义 CNI：展示 type 与 NAD 名称便于排查
  const type = config.type || 'Unknown';
  displayName = `${type} / ${nad.metadata.name}`;
}
```

### 2. 节点亲和性渲染：过滤 network.harvesterhci.io/mgmt In true

位置：节点调度区块的 `节点亲和性` 渲染

[HarvesterVmDetailDrawer.tsx](file:///d:/work/Compute.Tower/frontend/src/pages/Clouds/Harvester/components/HarvesterVmDetailDrawer.tsx#L2159-L2182)

```tsx
const nodeAffinity = vmData?.spec?.template?.spec?.affinity?.nodeAffinity;
if (!nodeAffinity?.requiredDuringSchedulingIgnoredDuringExecution) {
  return <span style={{ color: '#999' }}>未设置</span>;
}
const terms = nodeAffinity.requiredDuringSchedulingIgnoredDuringExecution.nodeSelectorTerms || [];
if (terms.length === 0) {
  return <span style={{ color: '#999' }}>未设置</span>;
}
const filteredTerms = terms.map((term: any) => {
  const exprs = (term.matchExpressions || []).filter((expr: any) => {
    const key = String(expr.key || '');
    const op = String(expr.operator || '');
    const vals: string[] = Array.isArray(expr.values) ? expr.values.map((x: any) => String(x)) : (expr.values ? [String(expr.values)] : []);
    const includesTrue = vals.includes('true');
    if (key === 'network.harvesterhci.io/mgmt' && op === 'In' && includesTrue) {
      return false;
    }
    return true;
  });
  return { ...term, matchExpressions: exprs };
}).filter((t: any) => Array.isArray(t.matchExpressions) ? t.matchExpressions.length > 0 : true);
if (filteredTerms.length === 0) {
  return <span style={{ color: '#999' }}>未设置</span>;
}
return (
  <div style={{ display: 'flex', flexDirection: 'column', gap: 8 }}>
    {filteredTerms.map((term: any, idx: number) => (
      <div key={idx} style={{ display: 'flex', flexDirection: 'column', gap: 4 }}>
        {term.matchExpressions?.map((expr: any, exprIdx: number) => (
          <Tag key={exprIdx} color="green" style={{ margin: 0 }}>
            {expr.key} {expr.operator} {Array.isArray(expr.values) ? expr.values.join(', ') : expr.values || ''}
          </Tag>
        ))}
      </div>
    ))}
  </div>
);
```

## 变更原因与边界条件

- kube-ovn 的 ovn-cluster VPC 表示扁平子网语义，需要直观呈现并保留子网名用于定位。
- mgmt 亲和性是系统性要求，展示会造成误读；过滤仅影响 UI 呈现，不更改后端数据。
- 若 NAD 或 Subnet 解析失败，保持原有兜底展示以避免空值。
