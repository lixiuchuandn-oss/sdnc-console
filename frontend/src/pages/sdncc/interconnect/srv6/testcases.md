# SRv6 隧道 · 发版前冒烟测试用例

> 适用范围：baseline + 贡献 + recompute 架构（P1–P4）上线后的手工验证。  
> 建议环境：具备四端 VR（PE-A、PE-B、CE-A、CE-B）的测试集群，管理员账号。

## 前置条件

- 四端 VR 已在「角色配置向导」中完成基础配置（PE 含 Locator、SID 前缀、公网 IPv6、内网 VRF 口；CE 含公网 IPv4/BGP）。
- 测试账号具备 `networks.srv6:read` / `networks.srv6:write` 权限。

---

## R1 · 新隧道创建与四端生效配置

| 项 | 内容 |
|----|------|
| **步骤** | 1. 进入 SRv6 创建向导，选择四端 VR，完成 PE/CE 互联参数<br>2. 点击「创建隧道并保存到平台」<br>3. （可选）进入下发向导，分步预览四端配置 |
| **期望** | 创建成功；提示「四端生效配置已由平台重算并写入库」<br>平台库中四端 VR 的生效配置 = 向导基线 + 本隧道贡献（可通过对账或库表抽查） |
| **失败信号** | 400/409 报错；四端配置未变化或缺少基线 |

---

## R2 · 删除隧道并回退配置

| 项 | 内容 |
|----|------|
| **步骤** | 1. 在隧道列表删除 R1 创建的隧道<br>2. 勾选「回退平台库中的隧道注入项」<br>3. 确认删除 |
| **期望** | 删除成功；四端 VR 生效配置回到创建前的向导基线（PE22 类场景） |
| **失败信号** | 400「缺少配置变更记录」或「尚未保存向导基线」；四端配置仍含已删隧道的邻居/路由 |

---

## R3 · Hub PE 多隧道（不同 neighbor / VRF）

| 项 | 内容 |
|----|------|
| **步骤** | 1. 在 R1 同 Hub PE 上创建第二条隧道 T2<br>2. T2 使用**不同**公网邻居或内网 VRF/内网口<br>3. 保存并查看创建页 Hub 提示、列表 Hub 标签 |
| **期望** | T2 创建成功；Hub PE 显示「Hub 多隧道模式」及已引用隧道列表 |
| **失败信号** | 误报冲突；Hub 标签未展示 |

---

## R4 · Hub 冲突拒绝（复用 neighbor）

| 项 | 内容 |
|----|------|
| **步骤** | 1. 创建 T3，与 T1 **复用相同**公网 BGP 邻居（或相同 RD/RT、内网口+VRF）<br>2. 点击保存 |
| **期望** | HTTP 409；toast 显示中文冲突说明（如「公网 BGP 邻居 x 已被隧道 xxx 使用」），**不**出现 C-N1、injectedDelta 等内部术语 |
| **失败信号** | 冲突隧道仍被保存；错误信息为英文或内部字段名 |

---

## R5 · 配置对账扫描与修复

| 项 | 内容 |
|----|------|
| **步骤** | 1. 隧道列表 →「配置对账」<br>2. 点击「重新扫描」<br>3. 若有问题项，点击「扫描并修复」<br>4. 系统设置 → 审计日志，检索 SRv6 Reconcile |
| **期望** | 正常时显示「暂无漂移项」；人为制造漂移后可检出中文问题描述并修复；审计有对账记录 |
| **失败信号** | 问题描述含 config_json、baseline+Σcontrib；修复后仍漂移 |

---

## R6 · 改 WAN 指纹不一致 → 保存 VR 配置

| 项 | 内容 |
|----|------|
| **步骤** | 1. 某 VR 已被存活隧道引用<br>2. 在 VR 配置页修改公网 IPv6 / SID 前缀等关键项并保存 |
| **期望** | HTTP 409；提示「已被 SRv6 隧道引用，关键配置不允许修改」，并列出中文关键项名称（如「公网 IPv6」） |
| **失败信号** | 静默保存成功；字段名显示 publicIpv6 等英文键 |

---

## R7 · 删除最后一条隧道 · 基线对齐

| 项 | 内容 |
|----|------|
| **步骤** | 1. 删除 Hub PE 上最后一条存活隧道<br>2. 打开「配置对账」扫描该 PE<br>3. （可选）`POST /api/networks/srv6/vr/:vrUuid/baseline/reset` 零隧道重置 |
| **期望** | 无隧道时向导基线与平台生效配置一致；对账无 ORPHAN 漂移；删除流程自动触发基线对齐 |
| **失败信号** | 无隧道仍报「与基线不一致」且无法修复 |

---

## 历史隧道（负向）

| 项 | 内容 |
|----|------|
| **步骤** | 对**无**关系档案/基线的旧隧道尝试「回退并删除」 |
| **期望** | 400/409 中文提示，引导取消回退仅删记录或使用配置对账 |
| **说明** | 不做旧数据自动兼容 |

## 相关 API（调试参考）

| 接口 | 用途 |
|------|------|
| `GET /api/networks/srv6/vr/:vrUuid/hub` | Hub 状态 |
| `GET/POST /api/networks/srv6/reconcile` | 配置对账 |
| `POST /api/networks/srv6/vr/:vrUuid/baseline/reset` | 零隧道基线重置 |
